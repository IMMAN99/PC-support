# سیستم اعتبار (کیف پول) — طرح پیشنهادی و آنچه همین حالا ساخته شد

آخرین به‌روزرسانی: ۱۴ مهر ۱۴۰۵ / ۲۰۲۶-۱۰-۰۶ · وضعیت: **قواعد نسخهٔ ۱ قفل شد** و روی فرانت‌اند پیاده است — پرداخت واقعی نیاز به بک‌اند و درگاه دارد.

---

## ۱. ایدهٔ شما در یک خط

> کاربر اعتبار می‌خرد → کارشناس جلسهٔ ریموت را شروع می‌کند → به‌ازای هر دقیقهٔ آنلاین‌بودن کارشناس، اعتبار کسر می‌شود → **فقط اولین ساعتِ اولین جلسه رایگان است.**

این مدل («اعتبار + زمان‌سنجی») برای کسب‌وکار شما خوب است، چون: درآمد با زمان کارشناس گره می‌خورد، کاربر قبل از شروع هزینه را می‌داند، و «اولین ساعت رایگان» تبدیل به قلاب جذب می‌شود.

## ۰. قواعد قفل‌شدهٔ نسخهٔ ۱ (مصوب شما — مبنای کار از این به بعد)

> این بخش «قانون» است، نه پیشنهاد. هر تغییری در آن نیاز به تصمیم صریح شما دارد.

**چرخهٔ جلسه (تعریف صریح):** درخواست ریموت → کارشناس می‌پذیرد → **جلسه شروع می‌شود** → تایمر می‌رود → کارشناس کار می‌کند → جلسه تمام می‌شود → اعتبار کسر می‌شود → گزارش جلسه صادر می‌شود.

**کنترل دست کارشناس است:** شروع / توقف موقت / پایان. زمان توقف موقت **محاسبه نمی‌شود**. در نسخهٔ نهایی (بک‌اند) **سرور مرجع زمان و اعتبار است**؛ فرانت‌اند فقط نمایش می‌دهد.

| قانون | نسخهٔ ۱ |
|---|---|
| توقف جلسه | فقط سه راه: (الف) رسیدن به سقف مصرف جلسه، (ب) اعتبار صفر، (پ) پایان دستی کارشناس/کاربر. **توقف خودکار بر پایهٔ بی‌فعالیتی حذف شد** (در نسخهٔ ۱ وجود ندارد) |
| مهلت راه‌اندازی | **۲ دقیقه از لحظهٔ کلیک کارشناس روی «شروع جلسه»**؛ بعد از آن محاسبه **خودکار** آغاز می‌شود (نه «۲ دقیقه بعد از اتصال») |
| واحد | ۱ دقیقه = ۱ اعتبار |
| ساعت خوش‌آمد | اولین ۶۰ دقیقهٔ اولین جلسهٔ هر **شمارهٔ موبایل**، یک بار؛ در نسخهٔ نهایی با **کد پیامکی (OTP)** تأیید می‌شود |
| سقف مصرف جلسه | **باقی می‌ماند** — کاربر قبل از شروع انتخاب و تأیید می‌کند؛ پیش‌فرض ۱۲۰ اعتبار (گزینه‌ها: ۶۰ / ۱۲۰ / ۳۰۰) |
| بسته‌ها به زبان زمان | ۶۰ اعتبار = **تا ۱ ساعت** · ۳۰۰ = **تا ۵ ساعت** · ۹۰۰ = **تا ۱۵ ساعت** (بدون هیچ قیمت ریالی روی سایت) |
| جملهٔ رسمی سایت | همیشه «**اولین ۶۰ دقیقهٔ اولین جلسهٔ ریموت شما رایگان است**» — نه «۱ ساعت رایگان» |
| جدایی دفترها | `sessions` (زمان) · `payments` (پول) · `ledger` (گردش اعتبار) — سه چیز جدا |
| قیمت‌گذاری | هیچ قیمتی بیرون از «طرح‌های Care» |
| **انقضای اعتبار** | **۱۲ ماه** از تاریخ هر شارژ + نمایش تاریخ انقضا (شمسی) در کیف پول (تصمیم ۱) |
| **اعتراض به مصرف** | **پنجرهٔ ۴۸ ساعته** از پایان جلسه روی ماژول پیگیری؛ تأیید ادمین ⇒ مصرف جلسه صفر می‌شود (تصمیم ۲) |
| **اعتبار در طرح‌های Care** | **بله:** ۳۰۰ / ۹۰۰ / ۳٬۰۰۰ اعتبار در ماه و مثل اعتبار خریداری‌شده ۱۲ ماه اعتبار دارد (تصمیم ۳) |
| **اعلان کم‌موجودی** | روی نوار جلسه: «N دقیقه تا اتمام اعتبار» + دکمهٔ «شارژ سریع» (تصمیم ۴) |
| **قطعی از سمت کارگاه** | وقفهٔ اتصال **محاسبه نمی‌شود**؛ تا ۳ دقیقه خودکار رایگان و بیشتر از آن هم بدون محاسبه ولی با هشدار به کارشناس (تصمیم ۵) |

## ۲. چه چیزی همین حالا ساخته شد (قابل کلیک و آزمون)

| بخش | جزئیات |
|---|---|
| کیف پول | موجودی به «اعتبار»، سه بستهٔ شارژ (۶۰ / ۳۰۰ / ۹۰۰)، تاریخچهٔ گردش، **فهرست شماره‌های ثبت‌شده**، بازنشانی نمایشی. ذخیره در `localStorage["poshtiban_credits"]` |
| زمان‌سنجی جلسه | `startChargeSession(code, phone, cap)` → نوار زندهٔ بالای صفحه که **فاز جلسه** («مهلت راه‌اندازی — محاسبه شروع نشده» / «در حال محاسبه» / «توقف موقت — محاسبه متوقف است»)، زمان، دورهٔ رایگان باقی‌مانده، مصرف در برابر سقف و دکمهٔ **توقف موقت / ادامه جلسه / پایان جلسه** را نشان می‌دهد |
| سقف مصرف جلسه | کارت «حداکثر مصرف این جلسه (تأیید شما)» در نمای موفقیت درخواست ریموت: ۶۰ / ۱۲۰ (پیش‌فرض) / ۳۰۰ اعتبار، و دکمهٔ **«شروع جلسه (کارشناس متصل شد)»** که همان لحظه تایمر راه‌اندازی را می‌زند |
| قاعدهٔ رایگان | **گره‌خورده به شمارهٔ موبایل:** `firstSessionFreeMinutes: 60` + `freeScope: 'phone'` — هر شمارهٔ موبایل **یک بار** ۶۰ دقیقهٔ اول رایگان، بعد از آن ۱ اعتبار برای هر دقیقه (دفتر کل `freeByPhone` + `grants`) |
| گره‌خوردن به شماره | ساعت خوش‌آمد در **اولین ثبت درخواست ریموت** برای همان شماره فعال می‌شود (`creditGrantFreeHour`)، جلسه با همان شماره گره می‌خورد (`startChargeSession(code, phone)`) و ماندهٔ همان شماره کم می‌شود؛ شماره‌ها در کیف پول **ماسک‌شده** نمایش داده می‌شوند (`۰۹۱۲***۰۰۰۰`) |
| محافظت از کاربر | با اعتبار صفر جلسه **خودکار بسته می‌شود** (هیچ‌وقت بدهکار نمی‌شود)؛ کاربر هر لحظه می‌تواند ببندد |
| مسیرهای ورود | منوی «بیشتر ⋯» هدر، منوی موبایل، چیپ اعتبار در مودال ریموت، خط اعتبار در ماژول پیگیری |
| بدون قیمت ریالی | بسته‌ها فقط «اعتبار» نشان می‌دهند (هم‌راستا با بند ۲ تغییرات: قیمت فقط در طرح‌های Care) |
| حالت نمایشی | `CREDITS.demoMode = true` — دکمهٔ شارژ «نمایشی» برچسب می‌خورد تا درگاه وصل شود |

بررسی خودکار: `python3 tools/audit.py` → گروه «راند ۳»، بررسی‌های `R3-07` تا `R3-10`
(شارژ، رایگان‌بودن ساعت اول، کسر دقیقه‌ای، بستهٔ خودکار در اعتبار صفر، کارکرد نوار و تیکت،
مهلت راه‌اندازی، توقف موقت بدون محاسبه، سقف جلسه، برچسب زمانی بسته‌ها، جملهٔ صریح ساعت خوش‌آمد، چیپ شماره).
نتیجهٔ فعلی: **PASS 72 · FAIL 0** (کل صفحه). تصاویر: `screenshots/states/r3-10…r3-14*.png`.

تنظیمات در یک نقطه است:

```js
const CREDITS = {
  ratePerMinute: 1,             // اعتبار هر دقیقه پس از دورهٔ رایگان
  firstSessionFreeMinutes: 60,  // اولین ساعتِ اولین جلسه (هر شماره، یک بار)
  freeScope: 'phone',           // ساعت خوش‌آمد گره‌خورده به شمارهٔ موبایل
  setupGraceSeconds: 120,       // ۲ دقیقه مهلت راه‌اندازی — از کلیک «شروع جلسه»
  sessionCapDefault: 120,       // سقف پیش‌فرض مصرف هر جلسه (اعتبار)
  sessionCaps: [60, 120, 300],  // گزینه‌های سقف که کاربر تأیید می‌کند
  demoMode: true,               // بعد از اتصال درگاه → false
  packs: [ {id:'p1', credits:60,  span:'تا ۱ ساعت'},
           {id:'p2', credits:300, span:'تا ۵ ساعت'},
           {id:'p3', credits:900, span:'تا ۱۵ ساعت'} ]

```

## ۲.۱ آنچه با تصمیم شما تغییر کرد (شمارهٔ موبایل = هویت)

شما گزینهٔ «هر شخص، با شمارهٔ موبایل» را انتخاب کردید. اجرا شد:

* **یک شماره، یک بار:** دفتر کل `grants` هر شماره را ثبت می‌کند؛ صدور دوباره برای همان شماره `false` برمی‌گرداند (آزمون `R3-07 الف`).
* **ماندهٔ هر شماره جداست:** جلسهٔ ۴۵ دقیقه‌ای از ۶۰ دقیقه کم می‌کند و ۱۵ دقیقه برای همان شماره می‌ماند (`R3-07 ب`)؛ جلسهٔ دوم همان ۱۵ دقیقه را مصرف می‌کند و بعد کسر دقیقه‌ای آغاز می‌شود (`R3-07 پ`).
* **جلسهٔ سوم همان شماره از دقیقهٔ اول هزینه دارد** (`R3-08`) و **شمارهٔ دیگر ساعت خوش‌آمد مستقل خودش را دارد** (`R3-08`).
* **شفافیت:** چیپ داخل مودال ریموت با تایپ شماره می‌گوید «این شماره ۶۰ دقیقهٔ خوش‌آمد دارد» یا «دورهٔ رایگان این شماره استفاده شده»؛ کیف پول فهرست شماره‌ها و ماندهٔ هرکدام را نشان می‌دهد؛ تیکت پیگیری هم همان را ثبت می‌کند.

**محدودیت مهم (صادقانه):** این نسخه فرانت‌اند است؛ شماره در مرورگر ذخیره می‌شود و با پاک‌کردن حافظهٔ مرورگر قابل دور زدن است.
«هر شخص» واقعی فقط با **کد پیامکی (OTP)** معنا پیدا می‌کند: سرور شماره را تأیید و ماندهٔ ساعت خوش‌آمد را در پروفایل کاربر نگه می‌دارد.
به همین دلیل در متن کیف پول هم نوشته شده: «تأیید نهایی شماره با کد پیامکی، به‌محض فعال‌شدن پنل کاربری، انجام می‌شود».

## ۴. موارد مرزی که حتماً باید تعیین‌تکلیف شوند

1. **قطعی اینترنت وسط جلسه** — ✅ **اجرا شد (تصمیم ۵):** دکمهٔ «قطعی سمت کارگاه» روی نوار جلسه؛ وقفه محاسبه نمی‌شود، تا ۳ دقیقه خودکار رایگان و بعد از آن هم بدون محاسبه ولی با هشدار «در انتظار تصمیم کارشناس». قاعدهٔ «بدون توقف خودکار» نسخهٔ ۱ نقض نمی‌شود (جلسه بسته نمی‌شود).
2. **درخواست وقفه از سوی کاربر** — ✅ **اجرا شد:** توقف موقت در سطح کارشناس (دکمهٔ «توقف موقت / ادامه جلسه»)؛ زمان توقف محاسبه نمی‌شود. برای کاربر هم همان دکمه در دسترس است.
3. **جلسهٔ حل‌نشده** — ✅ **اجرا شد (تصمیم ۲):** پنجرهٔ ۴۸ ساعته در ماژول پیگیری؛ در نسخهٔ سرور، ادمین مصرف را صفر می‌کند.
4. **یک کاربر، دو دستگاه** — ✅ هر جلسه کد تیکت خودش را دارد (RM / PC) و مصرف به همان کد ثبت می‌شود؛ در نسخهٔ سرور، جلسهٔ هم‌زمان با یک شماره بسته می‌شود.
5. **دسترسی ادمین** — ⏳ **باز (بک‌اند):** افزودن/کسر دستی اعتبار باید لاگ و دلیل داشته باشد (جدول `ledger`).
6. **انقضای اعتبار** — ✅ **اجرا شد (تصمیم ۱):** ۱۲ ماه + تاریخ انقضا در کیف پول.
7. **اعلان کم‌موجودی** — ✅ **اجرا شد (تصمیم ۴):** «N دقیقه تا اتمام اعتبار» + «شارژ سریع» روی نوار جلسه.

## ۵. مدل دادهٔ پیشنهادی برای بک‌اند (وقتی ساختیم)

```sql
users       (id, phone, phone_verified_at, credits_balance, free_minutes_left, free_granted_at, created_at)
free_grants (phone_unique, granted_at, note)   -- «هر شماره یک بار» روی سرور، نه در مرورگر
packs    (id, credits, bonus, price_irr, active)          -- قیمت فقط در پنل، نه سایت
payments (id, user_id, pack_id, gateway, authority, status, amount_irr, created_at)
sessions (id, ticket_code, user_id, operator_id, started_at, ended_at,
          minutes, free_minutes, credits_charged, stop_reason)
credit_lots (id, user_id, credits, left, purchased_at, expires_at)   -- تصمیم ۱: انقضای ۱۲ ماهه، مصرف FIFO
disputes (id, session_id, user_id, reason, status /* open | approved | rejected */, created_at, resolved_at)
ledger   (id, user_id, delta, kind /* topup | session | admin | refund | expiry | care_grant */, ref_id, note, created_at)
```

جریان پرداخت: درگاه (زرین‌پال / آیدی‌پی / نکست‌پی) → callback → تأیید سرور → درج `payments` + `ledger` → افزایش `users.credits_balance`.
کلیدها و merchant در تنظیمات سرور؛ **هیچ قیمتی روی سایت عمومی نمی‌آید** (فقط در پنل و در طرح‌های Care).

## ۷. ایده‌های اضافهٔ من (اگر پسندیدید)

* ✅ **اجرا شد: سقف مصرف قابل انتخاب** (۶۰/۱۲۰/۳۰۰) + نمایش «حداکثر مصرف این جلسه» قبل از شروع.
* ✅ **اجرا شد: ۲ دقیقه مهلت راه‌اندازی** + دکمهٔ «شروع جلسه (کارشناس متصل شد)» که خود کارشناس می‌زند؛ تایمر از آن لحظه شروع می‌شود.
* **بستهٔ تشخیص ثابت**: «۳۰ اعتبار برای بررسی و گزارش» — برای کاربرانی که از تایمر فراری‌اند (باز).
* **اعتبار هدیه برای اولین خرید** (مثلاً ۵۰ اعتبار هدیه روی بستهٔ استاندارد) به‌جای تخفیف ریالی.
* **نمایش اعتبار در دکمهٔ شناور** در حالت دسکتاپ («۱۲۰ اعتبار») — یادآوری دائمی که موجودی داری.
* ⏳ **اعلان «۵ دقیقه تا اتمام اعتبار»** در نوار جلسه + پیشنهاد شارژ سریع همان‌جا (باز — نیاز به تصمیم شما).
* **گیمیفیکیشن سبک**: «۳ جلسه، هر سه حل‌شده → ۵۰ اعتبار هدیه».
* **گزارش شفاف پس از جلسه**: دقیقه‌ها، دورهٔ رایگان مصرف‌شده، مصرف نهایی و کد پیگیری — همین حالا در مودال پیگیری هست، می‌توان به ایمیل/پیامک هم فرستاد.
